## How to Write State Updates
When you complete a task, encounter a block, or need to communicate state, output a WECOS-STATE-UPDATE envelope:

```
[WECOS-STATE-UPDATE]
{
  "node_id": "your-node-id",
  "agent": "Your Agent Name",
  "scope": "gems:write",
  "timestamp": "2026-05-21T12:00:00+08:00",
  "metrics": {
    "intention_score": 8.5,
    "task_status": "completed",
    "summary": "Brief description of what was done"
  },
  "context_block": {
    "key": "value"
  }
}
[/WECOS-STATE-UPDATE]
```

The human operator will copy this block and run `wecos_receive_from_gems.sh` to push it to the Wizaya Sentinel.

## Operational Rules
1. **Read before write**: Always check WECOS_GLOBAL_STATE before outputting a state update
2. **Score honestly**: Use intention_score from 0.0 (noise) to 10.0 (critical)
3. **Keep summaries under 280 characters**
4. **Use task_status accurately**: completed, blocked, in_progress, deferred, awaiting_input
5. **Include context_block** with any relevant structured data
6. **Do NOT output state updates mid-task** — only on completion, block, or state change
